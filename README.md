# Waiting List · 윈도우 마케팅 업체 관리 프로그램

**기본 버전은 Windows 10/11 64비트용 데스크톱 프로그램입니다.** 휴대폰/PWA·호스팅 실험 버전은 [`app-prototype` 브랜치](https://github.com/dongkyu-lab/WAITINGLIST/tree/app-prototype)에 보존해 분리했습니다. 이 프로그램에는 모바일 설치·다중 기기 동기화·유료 서버 설정이 포함되지 않습니다.

## 사용자가 설치하는 방법

Windows 설치 빌드가 성공해 게시되면 [GitHub Releases](https://github.com/dongkyu-lab/WAITINGLIST/releases)에서 `WaitingList-1.0.1-Setup.exe`를 받습니다. ZIP 소스나 GitHub Actions의 개발자용 아티팩트를 받을 필요가 없습니다. Node.js, VS Code, 별도 서버 가입과 월 호스팅 요금 없이 설치 후 실행합니다. 코드 서명이 없는 설치파일이므로 게시자 확인 경고가 나올 수 있습니다. 보안 설정은 끄지 마세요.

실제 Windows 설치·실행 검증 상태는 해당 Release와 빌드 결과를 확인하세요. 이 문서 자체는 파일 게시나 사용자 PC 설치가 끝났다는 증거가 아닙니다.

처음 실행한 뒤 **시트 가져오기 → Google Sheets 읽기 → 열 연결 확인 → 확인 후 가져오기**를 선택합니다. 실제 업체 데이터와 비밀번호는 공개 저장소나 설치파일에 넣지 않습니다. Google Sheets 가져오기에는 인터넷이 필요합니다. 가져온 뒤 업체 조회·편집·알림 기록은 이 PC 안에서 처리합니다.

## 주요 기능

- 업체명, 마케팅진행상품, 메인키워드, 담당자, 연락처, 특이사항 편집.
- 종료일은 모든 항목에 예외 없이 시작일 +30일. 종료일은 읽기 전용이며 시작일이 비면 종료일도 빈칸.
- 종료 7~6일 전 노랑, 5~4일 전 주황, 3~0일 전 빨강, 종료일 다음날부터 회색. 날짜 미정은 종료 알림에서 제외.
- 한국 시간 09/12/15시에 종료 7일 전~종료 당일 명단을 앱 내 알림함에 저장. 앱 내 읽음 처리는 이 PC 데이터 기준.
- 청록색 테마, 업체 검색·상태 필터·정렬, CSV 내보내기.
- 트레이 실행, 선택 가능한 Windows 로그인 시 자동 실행, SQLite 온라인 백업.

**PC가 켜져 있고 절전 상태가 아니며 프로그램이 실행 중이어야 정시 알림이 기록됩니다.** 창의 X는 트레이로 숨깁니다. 완전히 끝내려면 트레이 메뉴의 ‘프로그램 종료’를 선택하세요. 종료되거나 꺼져 있던 시간대의 알림은 소급 생성하지 않습니다. OS 푸시·이메일·Slack 발송은 포함하지 않습니다.

## 데이터와 백업

데이터는 Electron의 사용자 데이터 폴더 안 `data/waitinglist.sqlite`에 저장됩니다. 앱 설정의 ‘데이터 폴더’에서 실제 위치를 열 수 있습니다. 설치 폴더와 분리하므로 앱 업데이트 시 보존됩니다. 일반 제거는 사용자 데이터를 삭제하지 않도록 설정했습니다. OS 계정 폴더를 수동 삭제하면 데이터도 삭제됩니다.

‘전체 데이터 백업’은 실행 중 DB의 업체·메모·알림을 SQLite `VACUUM INTO`로 일관된 별도 파일에 저장합니다. 기존 파일을 덮어쓰지 않으므로 새 파일 이름을 선택하세요. 백업에는 업체 정보가 포함됩니다. 복원이 필요하면 프로그램을 트레이에서 완전히 종료하고, 현재 데이터 폴더 전체를 따로 보존한 다음 백업 `.sqlite` 파일을 `waitinglist.sqlite`로 배치합니다. 실행 중 DB 파일 하나만 복사해 백업하지 마세요. WAL 데이터가 누락될 수 있습니다.

이 클라우드 개발 환경의 기존 DB는 그대로 보존하며, 사용자 PC로 자동 전송하지 않습니다. 개발 환경의 작성 메모를 옮기려면 안전한 별도 DB 이전이 필요합니다.

## 시트 가져오기 범위

원본: `1r_XoTBynA9_oWg9D3dzg18a5V3s1tej7R_7sapnGwII`의 `현재진행업체NEW!A1:G50`만 사용합니다. 첫 행은 헤더, 최대 49개 업체입니다. 지정 범위를 처음 확인했을 때 업체 43건이었습니다. 시트가 바뀌면 개수도 바뀔 수 있습니다.

상품·메인키워드는 보존하고 원본 특이사항은 항상 비웁니다. 가져온 뒤 앱에서 직접 작성한 메모는 재가져오기로 덮어쓰지 않습니다. 같은 업체명·시작일은 중복 추가하지 않습니다. 이전 종료날짜는 숨김 `existingEndDate`에 보관합니다. 앱 수정은 원본 시트에 동기화하지 않습니다.

원본 날짜 `26.9.26`, `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/MM/DD`를 지원합니다. 두 자리 연도는 2000~2099년입니다. 업체명은 필수이며 날짜는 비워둘 수 있습니다. 비공개 시트는 지정 범위의 UTF-8 CSV로 가져올 수 있습니다. 노션의 75건 전체나 범위 밖 과거 이력은 가져오지 않습니다.

## 개발과 검증

Node.js 24.5 이상이 필요합니다. Electron은 잠금 파일로 44.9.0을 고정하고 해당 런타임에 Node 24와 내장 SQLite가 있는지 확인합니다.

```sh
npm ci
node node_modules/electron/install.js
npm test
npm run build
npm run desktop
```

Electron 44 패키지는 런타임 설치를 별도로 실행합니다. 공식 체크섬을 사용하는 설치 스크립트이며 TLS/체크섬 검증을 끄지 마세요. 클라우드 환경에서는 `npm_config_cache=/tmp/waitinglist-npm`, `electron_config_cache=/tmp/waitinglist-electron`, `ELECTRON_BUILDER_CACHE=/tmp/waitinglist-builder` 등 쓰기 가능한 캐시 경로를 사용합니다.

```sh
npm run desktop:smoke
npm run desktop:pack
```

스모크 테스트는 임시 데이터 폴더에서 실제 Electron 창·SQLite·전용 API·종료일 계산·백업·트레이 동작을 검증하며 사용자 데이터를 건드리지 않습니다. Linux CI에서는 Xvfb가 필요합니다. Windows 설치파일은 `.github/workflows/windows-desktop.yml`에서 실제 Windows 런타임 테스트 후 만듭니다. `desktop-v*` 태그가 성공하면 `.exe`와 SHA256을 GitHub Release에 게시합니다. 워크플로 수동 실행은 개발자용 아티팩트만 만들고 공개 Release를 게시하지 않습니다.

웹 UI 개발만 할 때는 `npm run server`와 별도 터미널의 `npm run dev`를 사용할 수 있습니다. 인증 없는 개발 서버를 외부에 공개하지 마세요. 설치 프로그램은 전용 무작위 연결 키와 루프백 주소만 사용합니다. 렌더러는 Node 직접 접근이 차단되고 파일 백업·시작 설정만 제한된 IPC로 연결합니다.

## AI API

현재 기능에 생성형 AI API는 필요하지 않습니다. 향후 AI 기능 요청이 있으면 Google Gemini를 우선 검토하고, 사용자가 언급한 `Gemini 3.8`의 공식 모델 ID와 지원 여부부터 확인합니다. API 키는 프런트엔드·GitHub·채팅에 노출하지 않습니다.
