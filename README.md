# flow · 마케팅 파트너 관리

React 대시보드와 Node.js 24 / Express / SQLite 서버로 구성한 배포용 웹앱입니다. 업체 정보와 특이사항 편집, 날짜에 따른 상태 표시, 앱 내 알림함을 제공합니다.

## 개발

```sh
npm ci
npm run server
# 별도 터미널
npm run dev
```

Node.js 24 이상이 필요합니다. Vite는 API를 3000번 서버로 프록시합니다. 개발 모드에서만 비밀번호 없이 사용할 수 있습니다. 개발 서버를 외부에 공개하지 마세요.

```sh
npm test
npm run build
```

## 배포

1. `.env.example`을 참고해 `.env`에 12자 이상의 `APP_PASSWORD`를 안전하게 설정합니다. 저장소에 커밋하지 마세요.
2. Node.js 24 호스트에서 `npm ci && npm run build && npm start`를 실행하거나, Docker 호스트에서 `docker compose up -d --build`를 실행합니다.
3. HTTPS를 제공하는 리버스 프록시를 3000번 포트 앞에 구성합니다. 배포 로그인 쿠키는 Secure이므로 HTTPS가 필수입니다. 프록시에서 Host와 X-Forwarded-Proto 헤더를 보존하고, 앱 포트는 프록시를 통해서만 접근하도록 제한하세요.
4. 서버를 항상 실행하고 인스턴스는 **1개**만 사용합니다. 서버리스·유휴 절전 호스트에서는 정확한 시간의 알림이 보장되지 않습니다.
5. SQLite 디렉터리에 영구 디스크를 연결합니다. Docker Compose는 `flow-data` 볼륨을 사용합니다. 운영 데이터 백업은 서버를 정지하거나 SQLite 온라인 백업 API로 수행합니다. 실행 중 DB 파일 하나만 복사하면 WAL 데이터가 누락될 수 있습니다.

공유 관리자 비밀번호 방식이며 개별 계정, 권한 분리, 비밀번호 찾기는 포함하지 않습니다. 비밀번호 변경 시 기존 세션도 삭제하려면 서버를 중지하고 `sessions` 테이블을 비운 뒤 재시작하세요. 데이터베이스 디렉터리 전체를 삭제하면 업체 데이터도 삭제되므로 피하세요. 실제 외부 배포와 도메인 연결은 아직 수행하지 않았습니다. Docker 구성은 제공하며 Docker 빌드는 실행 환경에 따라 별도 검증이 필요합니다.

## 날짜와 알림 규칙

- 한국 시간(Asia/Seoul)의 날짜로 계산합니다. 시작일을 추가·변경하면 **달력 기준 30일 후**로 종료일을 자동 계산합니다. 시작일이 유지된 편집에서는 종료일을 직접 조정할 수 있습니다.
- 8일 이상: 진행 중. 7~6일: 노란색. 5~4일: 주황색. 3~0일: 빨간색. 종료일 다음날부터 회색.
- 매일 한국 시간 **09시, 12시, 15시**에 종료 7일 전~종료 당일 업체 목록을 앱 내 알림함에 저장합니다. 종료된 업체는 제외합니다. 해당 시간대에 대상이 없으면 빈 알림을 만들지 않습니다.
- 서버는 15초마다 확인하고, 날짜·시간대별 SQLite 고유 키로 재시작 후 중복 알림을 막습니다. 정각 서버가 일시적으로 중단됐으면 같은 시간 내 재시작 시 한 번 생성합니다. 이전 시간대의 누락분을 소급 생성하지 않습니다.
- 앱은 30초마다 알림을 갱신합니다. 앱을 닫아도 실행 중인 서버에 기록은 남고, 다음 접속 시 볼 수 있습니다. 기기 푸시·이메일·Slack 발송은 포함하지 않습니다.
- 알림 명단은 생성 당시의 이력입니다. 이후 업체를 편집하거나 삭제해도 과거 알림에 남습니다. 모두 읽음 처리는 공유 워크스페이스 전체에 적용됩니다.

## 지정 시트 가져오기

대상: `1r_XoTBynA9_oWg9D3dzg18a5V3s1tej7R_7sapnGwII` / `현재진행업체NEW!A1:G50`.

앱의 **시트 가져오기**에서 공개 시트를 읽거나 CSV 파일을 업로드한 뒤 열 연결을 확인합니다. 첫 행은 헤더이며 50행·7열까지만 사용합니다. 업체명과 시작일은 필수이며, 날짜 형식은 `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/MM/DD`를 지원합니다. 파일은 UTF-8 CSV를 사용하세요. 최대 49개 업체를 가져올 수 있습니다. CSV에 상단 안내 행이 있다면 범위를 정확하게 준비해야 합니다.

헤더가 `특이`, `비고`, `메모`인 열의 값은 미리보기 전에 제거하고 선택 항목에서 제외합니다. 서버는 가져오기 저장 시 전달된 특이사항을 항상 빈 문자열로 강제합니다. 앱에서 직접 작성한 기존 메모는 재가져오기로 덮어쓰지 않습니다. 같은 업체명·시작일은 건너뛰며, 재가져오기는 기존 업체를 수정하지 않습니다. 가져온 종료일은 시작일+30일로 계산합니다.

앱 편집은 로컬 DB에 저장되며 Google Sheets와 양방향 동기화하지 않습니다. 비공개 시트 OAuth/서비스 계정 인증은 구현하지 않았습니다. 민감한 시트를 공개하는 대신 지정 범위 CSV로 가져올 수 있습니다.

노션 참고 링크와 시트는 최초 구현 환경에서 네트워크 프록시 403으로 접근하지 못했습니다. **실제 업체 데이터와 노션 세부 요건은 미반영**입니다. 샘플 업체를 운영 목록에 넣지 않았습니다. 네트워크 접근과 공유 권한이 준비되면 시트를 가져오고 노션 요건을 별도로 대조해야 합니다.

## VS Code

이 환경의 작업 폴더는 `/workspace/WAITINGLIST`입니다. 같은 클라우드에 연결된 VS Code에서 열면 작업 파일을 확인할 수 있습니다. 로컬 PC에는 코드가 자동 동기화되지 않으므로 GitHub에 저장한 뒤 clone/pull해야 합니다. 현재 작업을 원격에 푸시하지 않았습니다.
